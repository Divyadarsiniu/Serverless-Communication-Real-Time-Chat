# DynamoDB Database Design & Query Access Patterns

This document details the schema design, partition key strategy, index architecture, and query patterns utilized in Amazon DynamoDB for the real-time chat platform.

---

## 1. Authoritative Data Store Architecture

In this architecture, **Amazon DynamoDB is the sole authoritative source of truth**. Browser `localStorage` is used solely for client-side display caching and is never relied upon as persistent storage.

---

## 2. Table Specifications

### 2.1 Table: `chat_connections`
Manages stateful WebSocket sessions mapped to user identities. Supports multiple active devices/tabs per user.

- **Billing Mode:** `PAY_PER_REQUEST` (On-Demand)
- **Primary Key:**
  - **Partition Key (PK):** `connectionId` (String) – Unique socket connection ID generated by API Gateway.
- **Attributes:**
  - `userId` (String) – Cognito user identifier (`sub`).
  - `username` (String) – User display name.
  - `connectedAt` (String) – ISO 8601 UTC timestamp.
  - `ttl` (Number) – Epoch timestamp in seconds for automatic expiration (TTL = 2 hours).
- **Global Secondary Index (GSI):** `UserIdIndex`
  - **GSI Partition Key:** `userId` (String)
  - **Projection:** `ALL`
  - **Purpose:** Enables finding all active `connectionId`s for a recipient (`userId = 'X'`) in $O(1)$ query time without performing an expensive full-table `Scan`. Supports multi-device broadcasting.

```json
{
  "connectionId": "VwX8de94IAMCF3A=",
  "userId": "e4b6c31a-8219-4cb5-8278-df16a5b6c891",
  "username": "Bob",
  "connectedAt": "2026-10-06T14:00:00.000Z",
  "ttl": 1791295200
}
```

### 2.2 Table: `chat_messages`
Stores immutable conversation message records chronologically.

- **Billing Mode:** `PAY_PER_REQUEST` (On-Demand)
- **Primary Key:**
  - **Partition Key (PK):** `conversationId` (String) – Computed deterministically: `min(userA, userB) + "#" + max(userA, userB)`.
  - **Sort Key (SK):** `timestamp_messageId` (String) – Compound key: `{ISO_TIMESTAMP}#{UUID}`.
- **Attributes:**
  - `messageId` (String) – Unique message UUID.
  - `senderId` (String) – Sender user ID.
  - `senderUsername` (String) – Sender display name.
  - `receiverId` (String) – Recipient user ID.
  - `receiverUsername` (String) – Recipient display name.
  - `message` (String) – Text payload.
  - `timestamp` (String) – ISO 8601 UTC timestamp.
  - `status` (String) – `"delivered"` (recipient was active) or `"sent"` (recipient was offline).

```json
{
  "conversationId": "user_101#user_102",
  "timestamp_messageId": "2026-10-06T14:05:00.123Z#a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c6d",
  "messageId": "a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c6d",
  "senderId": "user_101",
  "senderUsername": "Alice",
  "receiverId": "user_102",
  "receiverUsername": "Bob",
  "message": "Hello Bob! Serverless WebSockets working properly.",
  "timestamp": "2026-10-06T14:05:00.123Z",
  "status": "delivered"
}
```

---

### 2.3 Table: `chat_users`
Directory of registered users for discovery.

- **Billing Mode:** `PAY_PER_REQUEST` (On-Demand)
- **Primary Key:**
  - **Partition Key (PK):** `userId` (String) – Matches Cognito `sub`.
- **Attributes:**
  - `username` (String)
  - `email` (String)
  - `avatarUrl` (String, optional)
  - `lastSeen` (String)
  - `isOnline` (Boolean) – Updated in real time based on active connection presence.

## 3. Query Access Patterns & Complexities

| Access Pattern | Target Table | Operation | Complexity |
| :--- | :--- | :--- | :--- |
| **Register active socket** | `chat_connections` | `PutItem` | $O(1)$ |
| **Delete dropped socket** | `chat_connections` | `DeleteItem` | $O(1)$ |
| **Find all active recipient sockets** | `chat_connections` | `Query` on `UserIdIndex` | $O(1)$ |
| **Store sent chat message** | `chat_messages` | `PutItem` | $O(1)$ |
| **Fetch history chronologically** | `chat_messages` | `Query(PK=conversationId, ScanIndexForward=True)` | $O(N)$ limited to query size |
| **List registered users** | `chat_users` | `Scan(Limit=100)` | $O(N)$ bounded |
| **Update user avatar** | `chat_users` | `UpdateItem(PK=userId)` | $O(1)$ |
| **Update presence on disconnect** | `chat_users` | `UpdateItem(PK=userId)` | $O(1)$ |
